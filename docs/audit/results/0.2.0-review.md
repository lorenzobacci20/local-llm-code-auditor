# Independent review of Local LLM Code Auditor 0.2.0

The review covers the public CLI, evaluation runner, synthetic dataset, generated reports and source-to-package delivery on branch `codex/portfolio-v0.2.0`. The baseline is [d2ae67f](https://github.com/lorenzobacci20/local-llm-code-auditor/commit/d2ae67f934eb7efeab45e4c6308d662997563819). The reviewer inspected changes independently of their implementers. Tests below use public synthetic inputs.

## Checks by risk area

| Audit | What was checked | Evidence and limits |
| --- | --- | --- |
| 01. Functional behavior | Repository → CLI → static findings or optional selector, audit and critic → report pair | Exercised CLI tests for static mode, partial and unavailable stages, preserved drafts and strict exits. A successful verdict still needs a reader to verify the evidence. |
| 08. Data consistency | Oracle, pipeline telemetry, report bytes, adjudicated response and selected answer key | The evaluation runner checks Markdown against JSON and deterministic rule IDs. Reviewed score binding to original run digests and the full selected ground truth. |
| 02. Security | Repository, context, model server, optional build and report destination boundaries | Inspected component-wise path checks, loopback-only transport, redirect/proxy policy, exact-path selection, model metadata preflight and fixed command arguments. Reviewed model content rendering and concurrency tests. Untrusted builds require OS isolation. |
| 15. Supply chain | Installable package, development dependencies and CI credentials | MIT license, zero runtime requirements, pinned direct development/build tools, SHA-pinned Actions, read-only workflow token and disabled persisted checkout credentials. CI installs wheel and sdist in separate environments. Hosted images and transitive package resolution vary over time. |
| 16. Privacy | Source, Git metadata, optional context, logs, drafts and report retention | Reviewed redaction before sampling and at transport, the absence of absolute repository paths in the model prompt, plus local model validation. Redaction is pattern-based. Raw reports and evaluation workspaces remain operator-controlled sensitive files. |
| 03. Persistence | Report pair and evaluation filesystem | The JSON is installed before its Markdown and includes a byte checksum. Treat a visible completed Markdown with its matching JSON as a pair. No database runtime or migration is part of the CLI. |
| 04. Integrations | Git subprocess and Ollama response handling | Static inspection and regression tests cover unexpected response bodies, incomplete replies, refused remote addresses and fallback. Real measurements are recorded separately in the benchmark evidence. |
| 05. Distribution | Operator installs a local CLI from wheel or sdist | No hosted deployment target, database change or automatic release publication. The release candidate is subject to maintainer approval. |
| 17. Recovery | Interrupted collection, missing model and interrupted output | Original repository remains the input. Completed report pairs are retained. A process killed during publication may leave an orphan sidecar or staging file. Rerun in a fresh workspace. Restoring an earlier exact model reply requires retaining its original artifacts. |
| 06. Concurrency | Simultaneous writes for repositories sharing a report folder and timestamp | Independent run of the concurrent-writer regression. Distinct names preserve each completed pair. Evaluation destinations must be new. |
| 09. Observability | Per-stage status, fallback, missing output and exits | Reviewed default versus strict exits, token and timing fields, and incomplete run reporting. A completed model request establishes transport completion only. |
| 07. Resource bounds | Source file selection, inventory budget, critic budget and process resources | Tested multibyte text and bounded selector inventory. The same-draft test checks the entire original draft reaches the critic. Overall RSS and cumulative filesystem I/O depend on the repository, Git and optional builds. |
| 10. Interface | Local CLI and Markdown/JSON outputs | No graphical application or interactive web UI. Checked CLI help via the packaging path and recorded demo output. Screen-reader certification and a browser UI test are outside scope. |
| 11. Regressions | CLI/config, privacy, model transport, source budgets and report generation | Independent Windows run across eight test modules returned 69 passed and three skipped. This sandbox cannot create all link types. Cross-platform CI provides separate evidence. Independently tested the invoice handler and the targeted EF and scorer regressions after corrections. |
| 13. Documentation | README, architecture, security policy, walkthrough and case study | Checked that readers can run a model-free fixture and locate configuration, output definitions and limitations. The benchmark report supplies evidence for experimental claims. |
| 14. Source of truth | Rules, dataset, measurements and release record | Runtime rule definitions own deterministic observations. Fixture contracts and tests own seeded expectations. Run artifacts own telemetry. Human adjudications are required for published quality measurements. |

## Findings and corrective checks

| ID | Severity and confidence | Observation | Corrective check |
| --- | --- | --- | --- |
| RULE-01 | Medium, confirmed | A comment mentioning a removed exception caused a HIGH migration finding. | At `ab28017`, the regression verifies comments, strings and a real throw in a migration. An independent synthetic migration reproduced the original false positive. |
| EVAL-01 | Medium, confirmed | A review and copied sidecar could agree while referring to a different original response or answer key. | The scorer checks the manifest stage digest, the response and the reviewed digest, plus the selected ground-truth bytes. The tamper regression rejects stale artifacts. |
| TEST-01 | Medium, confirmed | Both invoice handler contract probes stopped before executing because their destination already existed. | The probes now materialize a new child directory. Both c19 and c20 reached the public invoice handler and passed their distinct checks. |
| OPS-01 | Medium, confirmed | Small prompt budgets still allowed a whole oversized source file to be read for redaction. | Source and optional context use bounded file reads. Inspect the source truncation status. Git and framework analyzers have distinct collection costs. |
| ART-01 | Medium, confirmed | Default Git line ending normalization changed the published demo Markdown bytes, invalidating the paired JSON reference. | Byte-preserving attributes cover the example and published benchmark artifacts. Verify the example checksum on an exported Git tree. |

Scans and regression tests cover their selected inputs and rules. They do not certify arbitrary repository content, model accuracy, administrator-controlled local services, or the behavior of trusted builds. The dated candidate verdict and verification links are recorded separately in the final review.
